# КБЖУ Трекер и Помощник Питания

Telegram-бот для точного учёта КБЖУ (калории, белки, жиры, углеводы) по
голосовым сообщениям, тексту и фотографии блюда или продукта.

> Монетизация (триал + платная подписка) реализована в коде, но сейчас
> **отключена** (`PAYWALL_ENABLED=false` в `.env`) — все функции бесплатны
> для всех пользователей. См. раздел «Монетизация» ниже.

## Ключевой принцип точности

Вся арифметика (пересчёт нутриентов на 100 г → вес порции, суммирование
приёма пищи, остаток суточного бюджета) выполняется **только программным
кодом** в `src/services/calculation/`. LLM (Claude) используется исключительно
для интерпретации человеческого языка/изображений: разбора фразы или фото на
ингредиенты и веса — но никогда для вычисления итоговых цифр КБЖУ. Эталонные
значения нутриентов берутся из USDA FoodData Central (primary) или FatSecret
(secondary); Claude используется как fallback только если продукт не найден
ни в одной из официальных баз, и такой результат явно помечается как
оценочный (`isEstimated: true`, помечается в сообщении пользователю значком ⚠️).

## Архитектура

```
src/
  bot/                  — Telegraf-хендлеры, клавиатуры, форматирование ответов
  services/
    stt/                — транскрибация голоса (OpenAI Whisper)
    llm/                — парсинг текста и фото блюд/продуктов в ингредиенты (Claude)
    nutrition/           — источники эталонных нутриентов (USDA / FatSecret) + резолвер
    calculation/          — ЧИСТЫЕ функции пересчёта КБЖУ и коэффициентов сырое/готовое
    profile/              — расчёт суточной нормы (формула Миффлина-Сан Жеора)
    subscription/         — триал/пейволл (сейчас отключён), интеграция с Telegram Payments
  db/                   — Prisma client + репозитории
prisma/schema.prisma    — модель данных (пользователи, приёмы пищи, подписки, платежи)
tests/                  — unit-тесты для расчётной логики (vitest)
```

## Стек

- Node.js 20+ / TypeScript
- Telegraf (Telegram Bot API)
- PostgreSQL + Prisma
- OpenAI Whisper API — STT
- Anthropic Claude API — NLU/Vision
- USDA FoodData Central API (primary) / FatSecret Platform API (secondary) — база нутриентов
- Telegram Payments (YooKassa / CloudPayments provider token, либо Telegram Stars) — готово к включению

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и заполните ключи (Telegram bot token,
   OpenAI, Anthropic, USDA FDC, при необходимости FatSecret).
2. Поднимите PostgreSQL: `docker compose up -d`
3. Установите зависимости: `npm install`
4. Примените миграции: `npm run prisma:migrate`
5. Запустите бота в dev-режиме: `npm run dev`

### Тесты

Расчётная логика (КБЖУ, суточная норма, доступ по подписке, поиск нутриентов) покрыта unit-тестами:

```
npm test
```

### Сборка и запуск в проде

```
npm run build
npm run prisma:deploy
npm start
```

### Docker

Есть `Dockerfile` (multi-stage build) для самого бота и `docker-compose.yml`
для локального PostgreSQL. Для полного локального стека:

```
docker compose up -d          # PostgreSQL
docker build -t kbju-bot .
docker run --env-file .env kbju-bot
```

### CI

`.github/workflows/ci.yml` на каждый push/PR прогоняет `npm test` и `npm run build`.

## Функции

1. **Учёт КБЖУ по голосу или тексту** — `.ogg`/`.mp3` голосовое → Whisper →
   текст; либо пользователь сразу пишет текстом — оба пути дальше идут по
   одному конвейеру (`bot/handlers/mealProcessing.ts`): Claude
   (структурирование ингредиентов) → USDA/FatSecret/Claude-fallback (эталонные
   нутриенты на 100 г) → программный пересчёт на вес → сохранение в БД →
   сводка по приёму пищи и остатку суточной нормы.
2. **Учёт КБЖУ по фото блюда/продукта** — пользователь присылает фото готового
   блюда или отдельного продукта → Claude Vision определяет состав и
   оценивает вес порций по визуальным ориентирам (`services/llm/analyzeDishPhoto.ts`)
   → те же ингредиенты идут по тому же конвейеру точного расчёта, что и
   голос/текст (`bot/handlers/mealProcessing.ts`) — итоговые калории и БЖУ
   считаются программно, а не моделью. Вес по фото — это оценка, пользователю
   явно показывается предупреждение об этом.
3. **Онбординг** — анкета (пол/возраст/вес/рост/активность/цель, `/cancel` в
   любой момент прерывает анкету) → расчёт суточной нормы по формуле
   Миффлина-Сан Жеора.

## Монетизация (сейчас отключена)

Инфраструктура подписки полностью реализована, но не активна:

- `PAYWALL_ENABLED=false` в `.env` — доступ ко всем функциям открыт всем без
  ограничений и без расхода счётчика триала.
- Чтобы включить: поставь `PAYWALL_ENABLED=true`, заполни
  `TELEGRAM_PAYMENTS_PROVIDER_TOKEN` (или `USE_TELEGRAM_STARS=true` для оплаты
  звёздами Telegram) — дальше сработает готовый триал (3 дня или 10
  распознаваний, что раньше) и пейволл с `/subscribe` (месяц/3 месяца/год).

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Регистрация / анкета профиля / приветствие |
| `/cancel` | Прервать анкету онбординга |
| `/today` | Итоги КБЖУ за сегодня и остаток нормы |
| `/profile` | Показать профиль и суточную норму |
| `/subscribe` | Выбор и оплата плана подписки (пока не обязательна) |

## Учёт состояния продукта (сырое/готовое)

`services/calculation/cookingCoefficients.ts` хранит усреднённые коэффициенты
изменения массы продукта при готовке (например, гречка увеличивается в ~2.8
раза при варке, куриное филе теряет ~30% веса при жарке). Если пользователь
указал состояние продукта, отличное от того, в котором он обычно хранится в
базе нутриентов (USDA/FatSecret чаще всего хранят сырые продукты), вес
приводится к нужному состоянию перед пересчётом — сами табличные значения на
100 г при этом не изменяются.
